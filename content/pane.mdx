Something that's bugged me for a while: a design system exists twice. There's
the Figma file, where it's laid out on a board — grouped, labelled, all of it
visible at once. And there's the code, where the same system is a folder you
open one file at a time.

Working in either one, I'm never really looking at the system. I'm looking at a
component, guessing at the rest. And the two drift, because they're separate
things kept in sync by hand.

So I wanted to try the obvious thing and see what happened: what if the board
*was* the code? Every frame a real `.tsx` file on disk, arranged spatially,
live. Does iterating on a system get better, or does it just look nicer?

## What I tried

I built the canvas so it's organised the way a design system is, not the way a
file tree is — you group frames and name the groups, drag and resize them, and
they sit behind the components like sections do in Figma. There's a tokens file
you open from the toolbar and a light/dark switch for the whole workspace.

Underneath, the components are plain files. Git works, imports work, and an
agent editing them gets the same live board I'm looking at.

## What I found

The part that actually changed how it felt was propagation.

`Button.tsx` exports `ButtonRoot`, with every shared decision in one string at
the top of it. `Toolbar.tsx` next to it uses `ButtonRoot` five ways — icon-only
toggles, disabled, loading, danger, a primary with icon and label. Change the
gap or the padding in that one string and both frames move while you're still
typing.

That's a small thing on paper and it didn't feel small. Seeing a change land
across real usages at the same moment I made it is a different activity from
opening a preview and deciding it looks fine. I stopped guessing at the rest.

What I'm less sure about is whether it holds at scale. Two components prove the
mechanic; a real system is thirty, and I don't know yet whether a board that
size stays useful or just becomes another thing to pan around.

## Where it broke down

Locally this leans entirely on a Vite dev server and HMR. There isn't one on
Vercel, so the hosted demo does something else — the editor posts files into
each frame, which transpiles them in the browser with Sucrase and re-renders,
with Tailwind's browser JIT covering classes that didn't exist yet.

It works, but it isn't the same thing: edits live in memory, so a refresh
throws them away. Worth saying plainly rather than letting someone find out by
losing work.

## Still open

Whether spatial arrangement earns its keep past a certain number of components.
Whether tokens are the right seam to iterate from, or just the easiest one.
Whether any of this beats a good Storybook once the novelty wears off.

I don't know. That's roughly where I left it.
