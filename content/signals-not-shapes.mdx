Software is mostly handoffs. One part of a system produces something, another
has to work out what to do with it, and at every one of those boundaries
there's the same choice: the producer says what it means, or the consumer
guesses.

Guessing is cheaper to build. Look at the shape of the thing, infer the intent,
branch on it.

```ts
// The consumer decides what this is by looking at it.
if (Array.isArray(row.campaigns) && row.campaigns.length > 0) {
  return <ExpandableRow row={row} />
}
return <PlainRow row={row} />
```

That is a guess. It's a good guess, it passes review, and it's right about
every row it was written against. It also can't tell you when it stops being
right, because a wrong inference produces output shaped exactly like a correct
one.

## what guessing costs

- **every new case moves downstream.** the producer adds a variant, the
  consumer needs a release.
- **the rule lives nowhere.** it's spread across conditionals, and no single
  place says what anything means.
- **failure is silent.** nothing throws. you get a plausible result.

## the alternative is old and boring

Let the producer declare, and render the declaration.

```ts
// The producer already knows. It says so.
return row.has_nested_rows ? <ExpandableRow row={row} /> : <PlainRow row={row} />
```

The consumer never opens the payload. It has no opinion about which key the
children arrived under, how many there are, or whether this row type existed
last week.

I built an audit tool once where the backend's response shape varied per
account — different accounts have different problems at different depths, all
landing in one table. Rather than the frontend inspecting payloads to decide
what to draw, the backend put classifiers on the object headers.
`has_nested_rows` and friends. Absence declared something too: nothing on the
header meant render the following items normally.

The inferring one doesn't break. That's the part worth sitting with. It returns
a clean table with four rows quietly missing from it, and there is nothing in
the output that would tell you.

## what it costs the other way

It isn't free. A missing classifier meant a row silently didn't render — no
inference means no recovery either. And the vocabulary was an agreement rather
than a type, so it held exactly as long as both sides kept it.

But the shape of the trade is general: **whoever knows the answer should say
it.** Leaving it to be reconstructed doesn't remove the work. It moves it to
whoever is worst placed to do it, and hides it from whoever decides what things
cost.

## the same problem, unsolved

Which is where I keep landing on model output. You read it and infer your way
through — what's solid, what's invented, what needs checking before you use it.
Shape inspection, on prose. A confident wrong sentence is shaped exactly like a
confident right one.

We solved this for machines decades ago by making producers declare. Nothing
here declares anything, and most of the effort is going into better output —
which raises the value of the guess without removing it.
